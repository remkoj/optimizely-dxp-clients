## Tests and request id handling

Tests live in `test/` (vitest, root config: `optimizely-graph-client` is in `testedPackages` of `vitest.config.mjs`); run with `yarn vitest run --project optimizely-graph-client` after `yarn prepare` (dependants resolve the built `dist`).

- `ContentGraphClient` reads the request id from the Optimizely Graph response headers (`REQUEST_ID_HEADERS`: `correlation-id`, `x-request-id`, `x-correlation-id`; the real header name is **unverified** against a live tenant) in `_responseMiddleware` and keeps only the strings in a fixed ring of 8 (`_recentRequestIds`/`_recentOperations`). Never store the `Response`, `Headers` or `ClientError` on the client.
- Errors: the `ClientError` of graphql-request (thrown for non-2xx and, with the default `errorPolicy`, for GraphQL errors) is annotated with the own props `requestId` and `status` and is otherwise unchanged; with `errorPolicy: 'all'` a lean `OptiGraphRequestError` (primitives only, no `cause`) is thrown.
- Hot path rules (guarded by `test/client-hot-path.test.ts`): with `debug`/`query_log` off a request only does `Headers.get` lookups and ring writes; no `process.env` reads, no `JSON.stringify`, no body/header iteration, no cloning.
- Logging masks credentials with `maskSecret`/`maskHeaders` (`src/client/utils.ts`): `Authorization`, `cg-username` and `cg-roles`.

## Generated files

`src/admin-api/client/**` is generated by `@hey-api/openapi-ts` (plugins `@hey-api/typescript`, `@hey-api/sdk` and `@hey-api/client-fetch`) by `scripts/create-client.mjs` from:
```
https://cg.optimizely.com/app/swagger/swagger.json
```
Do not hand-edit — overwritten on every `generate` run.

The generated code is wrapped by the hand-written facade in `src/admin-api/`:

- `services.ts`: `ApiError`, `unwrap` and the service classes (`webhooks`, `definitionV3`, ...) that keep the positional signatures of the previous (`openapi-typescript-codegen`) client and turn the HeyAPI `{data, error, response}` result into a value or a rejected `ApiError`.
- `legacy-types.ts`: deprecated aliases of the previous model names (e.g. `ContentSource_V3` → `ContentSourceV3`).
- `index.ts`: `OptimizelyGraphAdminApi`, `createClient` (default export) and `isApiError`.
- `hey-api-wrapper` is deliberately **not** used here; the client instance is created per `createClient` call and signs requests through `hmac-fetch.ts`, which also reads the body of `Request` objects (HeyAPI calls `fetch(new Request(...))`).
- Path ids are URL-encoded (`w/1` → `w%2F1`); methods return a plain `Promise`.

```bash
yarn workspace @remkoj/optimizely-graph-client run generate
yarn workspace @remkoj/optimizely-graph-client run prepare
```

## Publish token and header

The webhook that Optimizely Graph invokes after a publish authenticates with a shared secret that travels in a **header**, not in the URL.

| Variable | Config property | Description |
| --- | --- | --- |
| `OPTIMIZELY_PUBLISH_TOKEN` | `publish` | The shared secret. `${VAR}` references are expanded with `dotenv-expand` (BSD-2-Clause; its only runtime dependency, `dotenv`, was already in the dependency tree), e.g. `${VERCEL_AUTOMATION_BYPASS_SECRET}`. A reference to an unset variable results in *no* token (a warning without the value is written to stderr), never in a partial secret. Values without a `${...}` reference are used as is; escape a literal `$` as `\$`. |
| `OPTIMIZELY_PUBLISH_HEADER` | `publish_header` | Header name that carries the token (`DEFAULT_PUBLISH_HEADER` = `X-OPTLY-PUBLISH`). Must be an RFC 7230 token, otherwise an error is thrown (without the value). May use `${VAR}` references. For Vercel Deployment Protection use `x-vercel-protection-bypass`. |

- `resolvePublishHeader()` and `DEFAULT_PUBLISH_HEADER` are exported from `./config`; the header name is available as `client.siteInfo.publishHeader` (required member of `OptiGraphSiteInfo`).
- The debug configuration print masks `publish`.
- Expansion is limited to these two settings and works on a copy of `process.env`; the CLI's `.env` loader (`graph-cli/src/context/env.ts`) already expands the files it loads, so the expansion in the client only acts on values that still contain a `${...}` reference.
- Tests: `test/publish-config.test.ts` (header/token resolution), `test/admin-api.test.ts` (request contract of the Admin API client), `test/hmac-fetch.test.ts`.
